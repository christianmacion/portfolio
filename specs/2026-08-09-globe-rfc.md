# Globe RFC — rotating earth with L1/L2/L3 market markers

## 1. Goal

Ship a **rotating 3D earth** as a permanent, visual proof of scope: "we work
the entire universe." L1/L2/L3 markers drop in real-time over the cities
where data is sourced. The globe becomes the portfolio's signature asset.

Why now: the portfolio already has the building blocks (1,679 LOC of globe
infra across `WorldView.astro`, `worldview.client.ts`, `EarthMap.astro`,
`CoverageGlobe.astro`, `earth-110m-countries.ts`, `gdelt-client.ts`,
`market-ticks.ts`). The globe code in `worldview.client.ts` (594 LOC, full
`d3-geo` `geoOrthographic` projection with graticule + pin animation) was
written, audited, and **deactivated in v12.W4** in favor of a simpler
"Live Data Terminal" inside the ⌘J modal. This RFC proposes to ship the
globe as the **portfolio's primary identity asset on the home page**, and
to also keep the ⌘J terminal for the live data-feed story.

## 3. Three options under evaluation

### Option A — Globe on the home page (HERO replacement)

Replace the headshot + bio in the hero with the rotating globe. Mark + name +
subhead + social-links stay. The globe IS the portrait — it answers
"who is this person" with "someone whose scope is the world."

Pros:
- Highest visual impact. The globe becomes the brand identity.
- Bryllim parity: she uses a portrait; you use a working globe. Same register (signature visual asset), different medium.
- Directly answers the brief: "shows our scope is the entire universe."

Cons:
- Largest placement: headshot currently anchors the 2-col layout. Replacing it changes the home-page IA.
- Highest perf cost on first paint (must wait for d3-geo + topojson lazy load).
- Mobile: a 3D globe at 280px reads small. May need to fall back to `EarthMap.astro` (static equirectangular) on mobile.

### Option B — Globe as a new home-page section (after hero, before stats)

Keep the Bryllim hero intact. Add a new `<section class="globe-flagship">`
between hero and stats. Globe is the **proof layer**: "we cover L1/L2/L3,
here's the world, and here's the data feed pulsing over it."

Pros:
- Doesn't displace the hero (lowest risk).
- The globe gets a real surface area: 720×360 viewBox minimum, full rotation
  cycle visible to a scroll-by visitor.
- Tells the L1/L2/L3 story cleanly: the section title + legend do the work;
  the rotation does the visual.

Cons:
- Adds a new section to an already-dense home page.
- Stats / story / markets sections below compete for attention.

### Option C — Globe replaces the ⌘J "Live Data Terminal" payload

Keep the ⌘J modal. Replace its current content (AIHistoryTimeline +
ChromeMarquee + status footer) with the rotating globe + L1/L2/L3 ticker +
status footer. The modal becomes a power-user "show me the world" view.

Pros:
- Zero change to home-page IA. Zero risk to hero.
- Re-uses every existing binding (`data-worldview-svg`, ⌘J hotkey, modal
  chrome contract).
- The 594 LOC of globe code activates immediately — just swap the modal's
  inner content.

Cons:
- Modal-only = only visitors who ⌘J see the globe. Lower reach than
  Option A or B.
- Doesn't ship the visual on first paint.

## 4. Recommendation: **Option B + C combined**

Phase 1 (this RFC, ships with shortcuts strip):
- **Activate the globe in the ⌘J modal (Option C).** Restore the
  `<svg data-worldview-svg>` binding, swap the AIHistoryTimeline out for
  the rotating globe + L1/L2/L3 ticker. Reuse existing client script
  unchanged. ~2-3 hours of work. Zero home-page IA risk.

Phase 2 (after Owner reviews Phase 1):
- **Add a globe flagship section on the home page (Option B).** Title:
  `LIVE COVERAGE · L1 / L2 / L3`. Subhead: the L1/L2/L3 legend. Body: the
  rotating globe + a thin L1/L2/L3 key. Reuse the `worldview.client.ts`
  Globe class but inline-mounted on the home page (not in a modal). This
  is the visual proof the brief is asking for.

Why phased:
- Phase 1 is the **safe activation** — it proves the globe code path works
  in the modal context, gets the lazy-load bundle on the wire, and lets the
  Owner see the globe without committing to the home-page IA change.
- Phase 2 is the **identity commit** — once the Owner has seen the globe
  working in the modal, deciding where it lives on the home page is a
  visual call, not a guess.

## 5. Visual specification

### 5.1 Markers (L1 / L2 / L3)

L1 = `Level 1` = direct exchange feed (NYSE, Nasdaq, JPX, LSE, SGX, PSE)
L2 = `Level 2` = consolidated tape (SIP, CTS, OPRA, FX ECNs)
L3 = `Level 3` = order-book depth (full depth-of-market, top 10 levels)

Marker semantics:
- L1 dots: solid amber, radius 3px, no ring
- L2 dots: solid amber, radius 5px, single hairline ring (1px stroke)
- L3 dots: solid amber, radius 7px, double hairline ring (2 concentric 1px strokes)

Color: amber `#B45309` (the only accent on the site). No other colors. No
gradients. No halos. The marker weight is the signal.

### 5.3 Rotation

- One full rotation = 90 seconds (matches existing `ROTATION_PERIOD_MS`)
- Auto-rotation pauses on `:hover` and on `prefers-reduced-motion: reduce`
- Rotation speed is non-negotiable; this is institutional, not arcade

### 5.4 Chrome contract

- Background: cream `#FAFAFA` (matches page surface)
- Globe sphere outline: 1px hairline `#E5E5E5`
- Graticule: 1px dashed hairline, 8° spacing, `#E5E5E5` at 60% opacity
- Landmasses: dot grid (same algorithm as `CoverageGlobe.astro`) `#0A0A0A` at 12% opacity
- Markers: amber as above
- Marker label (on hover only): city name + L1/L2/L3 chip, mono 11px, ink `#0A0A0A`

## 6. Performance budget

| Asset | Size (gz) | When loaded |
|---|---|---|
| `worldview.client.ts` (globe + ticker scheduler) | ~3 KB | Always (host page bundle) |
| `d3-geo` (lazy import) | ~10 KB | On ⌘J OR on globe section visible |
| `topojson-client` (lazy import) | ~2 KB | On ⌘J OR on globe section visible |
| `earth-110m-countries.ts` | ~107 KB raw / ~30 KB gz | Same |
| GDELT cache (24h TTL) | ~50 KB | Same |

Lighthouse target: ≥ 95 across the board. Currently portfolio is 100/100/100/100
on the existing pages; the globe must not regress.

Acceptance: with the globe section rendered on the home page, Lighthouse
performance score ≥ 92 (1-3 point headroom from current 100, since the
globe adds ~40 KB gz and a slow connection simulation will count it).

## 7. Accessibility

- `prefers-reduced-motion: reduce`: rotation stops, globe shows static
  front-facing view (lat 20°, lon 80°, matching Digos-to-Tokyo axis).
- Globe is `role="img"` with `aria-label="Live coverage map. 12 venues
  across 5 continents."`
- Each marker is `<circle>` with `<title>` for SR tooltip.
- Globe section has a heading (`h2`) and a sr-only text summary of all
  venues, so SR users get the same info as sighted users.
- Keyboard: globe section has no interactive elements (it's decorative +
  informational). The L1/L2/L3 legend below it is `aria-describedby` to
  the heading.
- Color contrast: amber `#B45309` on cream `#FAFAFA` = 4.6:1 (passes WCAG AA
  for non-text content). Landmass dots at 12% opacity are decorative, not
  informational.

## 8. Out of scope (deferred)

- Live order-book heatmap on the globe surface (would need a streaming
  data source and a WebGL layer; v2 candidate)
- Time-of-day terminator line (would add another animated layer; v2 candidate)
- City-level zoom on marker hover (would require a separate detail surface;
  ship as link to `/footprint` for v1)

## 9. Open questions for Owner

1. **Phase 1 only, or Phase 1 + Phase 2 together?** Phase 1 is 2-3 hours
   and safe. Phase 2 is a home-page section commit and needs visual review.
2. **City count:** 12 venues (above) is the proposed baseline. Add more
   (24? 36?) or stay tight?
3. **L3 cities:** the proposal marks L3 on US + EU + JPX only (where it's
   accessible). Add L3 to any specific venue Owner wants to call out?
4. **Mobile fallback:** on <720px viewport, show static `EarthMap.astro`
   (equirectangular 2D) instead of the rotating globe. OK with that?

## 10. Success criteria

- Phase 1: ⌘J modal opens, shows rotating globe + L1/L2/L3 markers + ticker.
  Lighthouse on home unchanged. Owner can verify by `⌘J` from any page.
- Phase 2: Home page renders the globe flagship section above the stats
  block. Sighted visitor sees rotation + markers within 2 seconds of
  landing. Lighthouse ≥ 92.

## 11. Time / cost

- Phase 1: ~2-3 hours. No new deps. Reuses all existing code.
- Phase 2: ~6-8 hours. Adds the home-page section + responsive fallback
  + a11y wiring.

Total: 1 working day. No specialty-agent dispatches needed; this is
front-end implementation work in the existing repo.
